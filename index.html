Summary

The Learn Classic ASP project is a practical guide for developers working with Classic ASP, a server-side scripting environment for creating dynamic web pages. It covers essential topics such as form handling, session management, file system operations, database interactions, and content delivery.

The project includes examples of input validation, session-based user management, file manipulation using the Scripting.FileSystemObject, and database operations with SQL scripts for setup. It also demonstrates sending various content types (JSON, XML, etc.) and handling redirects.

Error handling is managed globally using the global.asa file and locally within individual ASP files. Logging mechanisms, such as file-based and database logging, are also discussed. The project integrates modern web technologies like HTML5, CSS3, and JavaScript (ES6), along with libraries like UIkit, Highlight.js, and jQuery.

This resource is ideal for developers maintaining or upgrading legacy ASP applications, offering practical examples and best practices for effective development.

Page Routing Logic

  • Forms are submitted using POST or GET methods.
  • Backend operations are handled in files like form-post.asp, form-get.asp, and database-write.asp.
  • Session management is demonstrated in session-simple.asp and session-login.asp.

Error Handling and Logging

Error Handling

Error handling in this project is primarily managed in the global.asa file. The global.asa file contains event handlers for application-level and session-level events, which can be used to handle errors globally.

Key Points:

  1. Global Error Handling:
    • The global.asa file includes event handlers such as Application_OnStart, Session_OnStart, and Session_OnEnd.
    • These handlers can be extended to include error logging or custom error messages.
    • Relevant File: global.asa
  2. File-Specific Error Handling:
    • Individual ASP files handle errors using conditional checks and validations.
    • For example:
      • form-post-validation.asp and form-get-validation.asp validate user inputs and display error messages if required fields are missing.
      • database-write.asp and database-update.asp validate database operations and ensure required parameters are provided.
  3. Error Reporting:
    • ASP's built-in Err object can be used to capture and handle runtime errors.
    • Example:
      On Error Resume Next
      ' Code that might cause an error
      If Err.Number <> 0 Then
      Response.Write "Error: " & Err.Description
      Err.Clear
      End If
  4. Global Error Configuration:
    • IIS can be configured to display detailed error messages for debugging purposes. This is useful during development but should be disabled in production for security reasons.

How to Run the Project

To run the project, follow these steps:

  1. Set Up the Environment:
    • Install a web server that supports Classic ASP (e.g., IIS - Internet Information Services).
    • Ensure that ASP is enabled in the IIS settings.
  2. Configure the Database:
    • Import the SQL files located in the files/ directory into your database:
      • tb_countries.sql
      • tb_posts.sql
    • Update the database connection string in the global.asa file to match your database configuration.
  3. Deploy the Project:
    • Copy the entire project folder to the root directory of your web server (e.g., C:\inetpub\wwwroot for IIS).
  4. Access the Application:
    • Open a web browser and navigate to http://localhost/learn-classic-asp-master/default.asp.
  5. Test the Features:
    • Use the links on the main page (default.asp) to explore the various features of the project, such as:
      • Basic ASP concepts
      • Form handling
      • File system operations
      • Database interactions
      • Session management
      • Sending content (JSON, XML, etc.)
  6. Troubleshooting:
    • If you encounter errors, check the following:
      • Ensure that the database connection string in global.asa is correct.
      • Verify that the required permissions are set for the project folder.
      • Check the IIS logs for detailed error messages.
